8. Idempotent Ingest & Upload Workflow

A 6-stage defensive ingestion pipeline guaranteeing idempotent processing, schema detection, duplicate prevention, and zero database corruption.

STAGE 1 • RECEPTION & HASHING
Cryptographic SHA-256 Audit

Multi-part file received via /api/upload. Content hashed with SHA-256. If identical hash exists in file_uploads, system flags as duplicate and safely preserves existing records.

STAGE 2 • SCHEMA DETECTION
Header Sniffing & Role Assign

Reads header row regardless of file name. Sniffs required columns (e.g., invoice_no, bill_to, amount → invoices role). Rejects corrupt files or duplicate column headers.

STAGE 3 • NORMALIZATION
Defensive Type & Date Parsing

Handles date discrepancies (DD/MM/YYYY in payments vs MM/DD/YYYY in bookings vs ISO in invoices). Strips currency formatting ($1,500.00 → 1500.0).

STAGE 4 • STAGED COMMIT
SQLite Transactional Safety

Executes INSERT OR REPLACE within a database transaction. If any fatal validation error occurs, entire batch rolls back; corrupt partial data never enters production tables.

STAGE 5 • RECALCULATION
Deterministic Engine Re-run

Executes reconcile_finances() and get_requests_and_leads(). Recalculates overdue balances, credits, unbilled shoots, and working answers with zero cache drift.

STAGE 6 • REVIEW ROUTING
Ambiguity & Exception Queue

If a new contact cannot be linked to known canonical clients with >90% confidence, record is routed to Owner Review queue rather than performing an unverified false merge.

11. Owner Action State Machine & SQLite Persistence Model

Owner actions are strictly deterministic, explicitly confirmed, and persisted permanently to SQLite.

State 1
PENDING
Algorithmically flagged by evidence engine
➔
State 2
IN PROGRESS
Owner opened draft or initiated review
➔
State 3
RESOLVED
Owner confirmed completion with notes
OR
Alternative
DEFERRED
Snoozed for 24h with timestamp logged
SQLite Table Schema: owner_decisions

CREATE TABLE owner_decisions (
  action_id TEXT PRIMARY KEY,
  decision_type TEXT NOT NULL,
  status TEXT NOT NULL, -- 'pending' | 'in_progress' | 'completed' | 'deferred'
  owner_notes TEXT,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

🔒 Durable Guarantee: Decisions are written to disk in axeom.db. When the owner reboots the app or uploads a new file, their resolved/deferred decisions are preserved and not wiped out.
